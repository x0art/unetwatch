# Domain Docs

## Layout

**Single-context**: one `CONTEXT.md` at the repo root covers the whole project.

## Files

| File | Purpose |
|---|---|
| `CONTEXT.md` | Project context — architecture, conventions, key decisions |
| `docs/adr/` | Architecture Decision Records |

## Consumer rules

- Read `CONTEXT.md` at the start of any session to understand the project.
- Read relevant ADRs when making architectural decisions.
- If `CONTEXT.md` doesn't exist yet, create it as part of onboarding.
